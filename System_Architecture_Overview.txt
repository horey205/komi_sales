[KOMI SALES DASHBOARD - 시스템 아키텍처 개요]

1. 기술 스택 (Tech Stack)
   - Frontend: React 19 (UI 로직)
   - Build Tool: Vite (빠른 빌드 및 개발)
   - Styling: Tailwind CSS 4 (현대적이고 반응형 디자인)
   - Database: Supabase (실시간 클라우드 DB)
   - Deployment: GitHub Pages (정적 웹 호스팅)

2. 주요 컴포넌트 구조
   - App.jsx: 메인 관제탑. 데이터 로딩, 단계(Step) 제어, 통합 저장 로직 담당.
   - SalesList.jsx: 대시보드 메인 목록. 검색, 필터링, 신규 등록 및 진행 상태 확인.
   - Wizard.jsx: 상단 마일스톤 UI. 1단계부터 10단계까지의 흐름 시각화.
   - 폼 컴포넌트: 각 단계별 특화된 입력창 (상담, 견적, 납품, 검수, 결제 등).

3. 데이터 흐름 (Data Flow)
   - (조회) Supabase 'sales' 테이블에서 전체 목록을 불러와 리스트에 표시.
   - (선택) 특정 업체를 클릭하면 ID를 기반으로 상세 데이터를 'editingRecord' 상태에 로드.
   - (편집) 각 단계의 폼에서 데이터를 입력하면 부모(App.jsx)가 실시간으로 통합 객체를 업데이트.
   - (저장) '저장' 버튼을 누르거나 단계를 이동할 때 Supabase에 JSON 형태로 전체 데이터를 업로드.

4. 핵심 기능 로직 (Main Logic)
   - 진행 상태 고정 (maxStep): 뒤쪽 단계(예: 계약)까지 간 기록은 앞쪽 단계(예: 상담)를 수정하더라도 목록에는 최종 단계가 유지되도록 설계됨.
   - 데이터 복사 (Copy Previous): 이전 단계(1차 견적 등)에서 작성한 품목 정보를 다음 단계(2차 견적, 계약 등)로 그대로 가져와 오타 방지 및 작업 속도 향상.
   - 잔금 정산 (Auto Balance): 계약 대금에서 현재까지 입력된 결제 금액을 실시간 산술 계산하여 잔여금 표시.

5. 데이터 보존 구조 (DB Schema - 'sales' table)
   - id: 고유 식별 번호
   - client_name: 업체명 (목록 검색용)
   - current_step: 최종 도달 단계 (목록 정렬 및 필터용)
   - data: [JSON 필드] 모든 상세 내용(상담내역, 견적품목리스트, 상세결제로그 등)을 통째로 보관
   - updated_at: 최근 수정 시간

6. 라우팅 (Routing)
   - Hash 방식 사용: 
     * #list : 업체 목록 페이지
     * #edit/[ID] : 특정 업체 상세 편집/조회 페이지
